# MERCY

## Project versions

- **[v1 — Original release archive](v1/README.md):** a preserved snapshot of the website, local LLM, voice, memory, animated face and first autonomous speech. The [archive/v1.0 branch](https://github.com/luckyy1711/mercy/tree/archive/v1.0) retains the complete old files and model weights.
- **[v2 — Cognition](v2/README.md):** local evidence-backed facts, corrections, narrow inference, learning from explicit teaching and curiosity proposals.
- **[v3 — Perception](v3/README.md):** permission-gated camera with private scene-change and lighting metadata, not object recognition.
- **[v4 — Embodiment](v4/README.md):** a physically bounded **virtual-only** motor simulator and a hardware interface abstraction, not a connected skull.
- **[v5 — Research and supervision](v5/README.md):** bounded curiosity planning, cognition diagnostics and experiment proposals—not autonomous neural retraining.

**Status:** v2–v5 are early, testable software prototypes, not fully developed versions of the advanced AI capabilities envisioned in the roadmap. Their small, lightweight modules are wired into the current website's **Cognitive Lab** without replacing Mercy's local language model, user-controlled autonomy or original browser voice. No verified sentience is claimed.

**Try it:** Open [MERCY](https://luckyy1711.github.io/mercy/), expand **Mercy Cognitive Lab · v2–v5**, and teach a fact. Then ask for it in chat or correct it. Test the optional private camera and virtual motor simulator independently.

The live website remains at **[GitHub Pages](https://luckyy1711.github.io/mercy/)** and is still served from the **repository root**. Version folders archive or stage major milestones; don't rename or move the production root just to release a new version. Large model weight files are kept only once in root `models/` to avoid duplicating hundreds of megabytes in the Pages artifact. Visitor memories are kept locally in each browser and are not part of GitHub backups.


MERCY is a gothic animatronic character prototype. The current experience is a **static browser voice/chat app** hosted at https://luckyy1711.github.io/mercy/.

The web prototype and the original Arch Linux Python microphone prototype are **separate**. The web app does not use the Python files.

## Browser prototype

- Type a message or speak through a browser that supports Web Speech Recognition.
- Replies come from **SmolLM2-360M-Instruct**, a small (roughly 363 MB int8 weights) generative model running locally in the browser through Transformers.js / ONNX Runtime Web.
- The browser uses its own speech-synthesis voice to speak the generated text (original voice settings are fixed at 0.75× speed and 0.45 pitch).
- The model starts automatically on page load. It is hosted in this GitHub repository under `models/`; the large ONNX file is split into chunks, which `sw.js` streams back as one file. Model data still **must transfer to each visitor's browser on first use**.
- Conversation memory is stored in the visitor's browser using localStorage, not in GitHub or a server. **Clear Mercy's memory** clears this saved conversation.
- The upgrade from the old 135M model keeps personal facts and archived conversation in the same browser, but starts a new short dialogue context for more relevant replies. A simple greeting intentionally excludes old questions from the generation prompt. Clearly unrelated model-generated greetings get one model-generated retry.
- Mercy has a fictional identity and a conversation log, **not real or verified consciousness**.
- An animated SVG skull provides eye tracking, occasional blinks, subtle head motion and a talking jaw. It is lightweight, runs on the device, and respects reduced-motion preferences.
- **Autonomous speech is opt-in and off on every page load.** Press **Enable autonomous speech** to allow Mercy to generate his own short thought when the visitor has been idle for about 55 seconds. Remarks are at least 125 seconds apart and stop after three without fresh interaction. It never initiates in a hidden tab; disabling the mode or pressing Stop cancels spontaneous speech. A working local AI is required.
- Autonomous remarks are generated by the same local SmolLM2 model, not a prerecorded script; they are also kept in the local conversation history. Audio playback uses the existing browser voice.
- First access requires internet to fetch site, model, inference runtime and WASM assets. Offline operation depends on successful caching of all required files and on installed browser speech voices. Browser speech recognition might still require network access.

### Browser limitations

A 360M-parameter model is still small: it can hallucinate, repeat itself, misunderstand questions, or run slowly on older CPUs. Some devices cannot initialize the ONNX runtime or fit the model in memory. The site shows errors and provides a **Retry AI startup** button when loading fails. There is no API key or cloud AI endpoint. Internet connectivity itself does **not** enable web searching.

### Architecture

```
index.html (UI + Web Speech)
    → presence.css + presence.js (animated expression + gaze)
    → autonomy.js (optional idle / visible-tab scheduling)
    → mercy-modes.js (local AI inference + conversation memory)
    → Transformers.js and ONNX Runtime Web
    → hosted SmolLM2 model chunks (GitHub Pages)
sw.js streams the chunked ONNX model and caches the app shell
```

### Updating hosted model weights

`.github/workflows/vendor-mercy-model.yml` is an optional GitHub Actions job that fetches model assets from Hugging Face, splits the ONNX model into GitHub-compatible parts and commits them under `models/`. It runs on edits to that workflow or when manually dispatched, not on every page view. The pipeline and service worker must agree on the model ID and ONNX filename.

All external model and library licenses remain in force. See `models/onnx-community/SmolLM2-360M-Instruct-ONNX/ATTRIBUTION.txt`.

## Legacy Python prototype (optional)

`main.py`, `mercy/brain.py` and `mercy/voice.py` implement the earlier laptop-only Vosk / espeak-ng voice experiment, **not** the browser AI. Its responses are scripted unless a separately configured local Ollama instance is running. It is retained as a starting point for future robotics work.

On Arch Linux:

```bash
sudo pacman -S --needed python python-pip portaudio espeak-ng unzip git curl
git clone https://github.com/luckyy1711/mercy.git
cd mercy
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
mkdir -p models
curl -L -o /tmp/mercy-vosk.zip https://alphacephei.com/vosk/models/vosk-model-small-en-us-0.15.zip
unzip /tmp/mercy-vosk.zip -d models
python main.py
```

This older program optionally uses `MERCY_OLLAMA_MODEL` and `MERCY_OLLAMA_URL` environment variables to contact a **locally running** Ollama model. No such Ollama configuration is required for the website.

## Tests

```bash
python -m unittest discover -s tests -v
node --check mercy-modes.js
node --check sw.js
node --check autonomy.js
node --check presence.js
node --test tests/*.test.cjs
```

The repository's CI workflow runs these tests and validates that the model manifest agrees with its committed chunks. Additional v2–v5 tests check correction persistence, limited inference, privacy, bounded curiosity, virtual actuator safeguards and the browser integration. An optional `.github/workflows/model-smoke.yml` workflow reconstructs the hosted 360M model to test actual inference in GitHub Actions. A real browser smoke test is still required for speech synthesis, service worker interception and local ONNX inference.
